**5.2 Data Sources, Readiness Assumptions, and Privacy Pre-Processing**


|Data Source Type|Specific Hospital Dataset / Artifact|Operational Role in Chart Ready AI|Key Data Assumptions & Hygiene Controls|
|---|---|---|---|
|Internal Clinical Data|General Surgery Discharge Summaries & Operative Notes (PDF / HL7 text)|Primary runtime input for completeness checking and ICD-10 code suggestion.|Assumes digital text or >=200 DPI scan; local regex + NER redacts Patient Name, Phone, Address, and Aadhaar/ABHA before LLM API call.|
|Internal Historical Records|12 Months of Audited General Surgery Coded Claims (~5,000 charts) & TPA Denial Logs|Identifies the top 30–50 surgical ICD-10 codes and builds the 200-chart Golden Evaluation Set.|Historical codes must be filtered to only claims that passed TPA settlement without coding queries (avoiding learning past coder errors).|
|External Standards & Ontologies|WHO ICD-10 (2019/2026) Official Tabular List, CMS Coding Guidelines, & NABH 6th Ed. Checklist|Populates the Vector RAG knowledge base with official definitions, inclusion/exclusion rules, and completeness criteria.|Publicly verifiable regulatory standards ([WHO ICD-10](https://icd.who.int/browse10/2019/en); [CMS Guidelines](https://www.cms.gov/files/document/fy-2025-icd-10-cm-coding-guidelines.pdf)).|
|User-Generated Telemetry (HITL)|Live Coder Accept / Edit / Reject actions, Override Reason Codes, and Physician Sign-off timestamps|Provides continuous ground-truth feedback for prompt refinement, confidence calibration, and drift audits.|Stored in immutable hospital audit tables with reviewer ID and dwell-time metadata to filter out accidental clicks.|
