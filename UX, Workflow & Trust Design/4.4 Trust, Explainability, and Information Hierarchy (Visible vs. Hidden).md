**4.4 Trust, Explainability, and Information Hierarchy (Visible vs. Hidden)**

To prevent cognitive overload while maximizing clinical trust, we carefully govern what information is surfaced vs. abstracted:

|UX Layer|What Must Be Visible to the User|What Should Be Hidden / Abstracted Away|Why This Design Choice Builds Calibrated Trust|
|---|---|---|---|
|Completeness Checklist Panel|Explicit pass/fail icons (✓ / ✗) for all 5 mandatory fields + direct jump-link to the section in the document.|Raw regex/token probability vectors and intermediate OCR bounding-box JSON coordinates.|Allows Deficiency Officers to verify in 2 seconds whether a flagged deficiency is genuine.|
|ICD-10 Code Suggestion Cards|Official ICD-10 code, description, calibrated tier badge (High >=85%, Med 65–84%, Low <65%), and verbatim highlighted quote.|Unconstrained raw LLM chain-of-thought tokens, temperature settings, and embedding cosine similarity decimals.|Coders think in clinical evidence and coding rules, not vector math; verbatim quotes prove the code is grounded in physician text.|
|Exclusion & Coding Rule Alerts|Plain-language ICD-10 instructional notes (e.g., 'Check Excludes1 rule: K35.20 already includes peritonitis').|Backend prompt system instructions and multi-step RAG retrieval logs.|Prevents duplicate coding errors (upcoding) that trigger TPA claim denials.|
|HITL Submission Gate|Live counter of unresolved flags ('2 of 3 codes reviewed; 1 deficiency pending') and locked export button.|Database write transaction payloads until final human confirmation is complete.|Guarantees zero silent pass-through of unreviewed AI predictions.|
